Docker answer: You do not need Docker to develop the portal or dashboard, or to run the Convex CLI against the already-running shared dev service. Docker Desktop is only needed for the optional local dashboard container shown above. The shared Convex host itself is already remote, and the Docker command is not available on this machine’s PATH. See the Convex CLI guide and self-hosted deployment guide.

The portal and dashboard currently have no Convex dependency or client setup in source. The backend package currently has no schema or functions. Running pnpm exec convex dev is a shared-backend write operation once there is backend code, so coordinate before running it.

What each package actually contains

Candidate website

portal/

Next.js App Router, React, Tailwind. Its only route is /, displaying “Hello world!”. mediasoup-client and socket.io-client are listed but never imported.

Recruitment website

dash/

Separate Next.js App Router app. Its only route is also /, with the same placeholder. It has no candidate list, interviewer UI, or connection to the backend.

Data / application logic slot

backend/

Only a package manifest with convex. There is no Convex schema, query, mutation, authentication, or API implementation.

Interview media slot

sfu/

Only a package manifest with mediasoup and socket.io. There is no running SFU, signaling server, room, or meeting logic. “SFU” means a server that forwards participants’ audio/video streams.

Package names and dependencies suggest intended roles. They do not establish a working integration.

Technical foundations and boundaries

  • Workspace: pnpm with four packages and a central dependency catalog. The root declares Node ^24.11.0 and pnpm 12.15.0.
  • Web apps: separate Next.js 16 canary / React 19 canary applications. Their configs enable React Compiler, component caching, partial prefetching, and Tailwind through Turbopack.
  • Tooling: root Vite+ formatting/lint configuration; package scripts only for developing, building, and starting the two web apps.
  • Missing system contracts: no shared types, database schema, API routes, environment examples, deployment definition, CI, or tests in this snapshot.

Architecture conclusion: this is a four-package monorepo skeleton connected to a team-provided shared development service, but the repository has not implemented its data flow. Candidate → round → task/interview → evaluation → decision remains unbuilt, and the portal, dashboard, and backend have no working Convex integration in this snapshot.
